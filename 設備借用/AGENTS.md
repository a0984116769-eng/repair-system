# 專案規則：工地設備借用登記系統

這份規則適用於 `設備借用/` 資料夾。需求以同資料夾的 `需求筆記.txt` 為準；筆記沒寫明的事，先問，不要自己決定。

## 開工前

- 每次開工，先把工作區更新成 GitHub 上最新的 `main`，再開始修改：

  ```bash
  git fetch origin
  git checkout -B <工作分支> origin/main
  ```

- 動手前先看清楚 `main` 上已經有哪些檔案，不要覆蓋別人已經合併的成果。

## 金鑰與機密

- 前端和任何設定檔只能使用 Supabase 的 **publishable key**（`sb_publishable_...`）。
- **secret key**（`sb_secret_...`）、service_role key、資料庫密碼、存取權杖（token）**不可以寫進任何檔案**，包括程式碼、設定檔、文件、SQL、測試資料和提交訊息。
- 需要用到 secret key 的工作（例如管理後台、排程清除資料），只能在 Supabase 後台或伺服器端環境變數中設定，不進 Git。
- 發現已經有機密被提交，立刻停止並告知負責人，不要自行改寫歷史。

## 資料與隱私

- 範例、測試資料、截圖一律使用虛構的姓名、班組、協力廠商與工地，不使用真實姓名或客戶資料。
- 資料表必須先啟用資料列安全（RLS），再讓網頁連線。
- 權限依登入身分設計：工人只能新增自己的借用單；只有工務或倉管能登記歸還與損壞；工地主任只能讀取；任何人都不能刪除紀錄。

## 檔案位置

- 需求與規則：`需求筆記.txt`、`AGENTS.md`
- 網頁前端：放在這個資料夾內，純 HTML／CSS／JavaScript
- Supabase 建表與存取規則：`supabase/`
- Excel、PowerPoint、Word 等使用者文件：`文件/`

需要時才建立資料夾。

## 撰寫慣例

- 介面文字、註解、文件使用繁體中文，保留需求筆記中的欄位名稱與意義。
- 網頁要能在手機上順利操作。
- 顯示使用者輸入的內容時一律當成純文字，不可直接插入 HTML。
- 修改保持聚焦，不做無關的格式調整。

## 完成後

1. 提交訊息用簡短的繁體中文，說明做了什麼。
2. 推送工作分支到 GitHub。
3. 用 GitHub 外掛建立 Pull Request，標題用繁體中文，說明內容包含：改了什麼、怎麼驗證、對應的需求。
4. 用 GitHub 外掛把 Pull Request 合併進 `main`，並確認 `main` 上已經有這次的改動。
5. 回報時說明沒有測試到的部分，不要宣稱未驗證的事情已經完成。
